# DEMAND CARD：需求→技能 Gap→验证→迁移

- demand_id：`LOCAL-YYYYMMDD-001`（不要伪造真实业务）
- status：`DESIGNED / IN_PROGRESS / EVIDENCED / INCONCLUSIVE`
- demand_type：`SELF_CHOSEN / SYNTHETIC / AUTHORIZED_TASK / HISTORICAL`
- demand/source/date：不存用户敏感内容；需要授权/来源时间时只放原仓脱敏引用
- **具体问题**（一句话描述输入、当前错误和期望）：
- **约束**（GPU/成本/时间/数据许可/SLO）：
- **非训练基线**（规则/Prompt/API/RAG 是否足够）：
- **主要指标**（任务级、独立 test）：
- **护栏指标**（延迟、成本、正确权限、安全、失败/拒答）：
- **失败样例**（至少两个不同类别）：
- **当前知识 Gap**：
- **必要前置**（只列本次用到的 1–3 个）：
- **对应 M01–M12 和权威来源/版本**：
- **代码/命令/数据快照**：
- **受控变量与对照组**：
- **测试结论**：事实 / 推断 / 尚未解决
- **独立陌生任务**：如何换一组输入复现/迁移？
- **是否真需上线**：YES / NO（YES 才执行生产门禁）
- **证据链接和 commit**：实际工程日志归项目仓；此处仅记录引用
- **停止条件**：达到何种证据即可停止钻研，什么时候重新打开

## 审核红线

- 无真实运行证据不填 EVIDENCED；单元测试 PASS 不等于学习者独立掌握；
- 模型不训练的基线已经足够好时，允许结论为“无需训练”；
- 运行失败同样保留事实，不能为了漂亮的报告只选成功样例；
- 紧急项目和学习兴趣分开排期，但不对任何知识点设永久禁区。
