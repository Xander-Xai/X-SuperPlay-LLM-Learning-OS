## R06｜Query 理解、改写与路由

| 方法 | 机制 | 适用 / 风险 |
|---|---|---|
| Rewrite | 多轮指代解析、拼写归一、规格/时间补全 | 增加可检索词；可能扭曲问题 |
| Query Expansion | 同义词/别名/行业术语扩展 | 覆盖召回；可能召来无关文档 |
| Multi-Query | 多角度并行查询、去重融合 | 多跳问答；成本上升且排序偏置 |
| HyDE | 生成假设答案并编码来找近邻 | 语义补足；假设本身不是证据 |
| Routing | FAQ/BM25/Dense/SQL/网页/人工等工具选择 | 便宜快；路由失误会漏答 |
| Metadata filter | tenant、product_id、version、valid_on | 精准且安全；过滤写错会漏召 |

多轮例：“这个成分上限多少？”→“欧盟呢？”重写要保留原成分/目标市场，不能擅自将 EU 解释成中国。记录 original_query、rewritten_query、reason、retrieved_ids、query_version，能回滚原问题检索。失败注入：错别名、否定条件被删除、对话历史混入另一个客户数据。

## R07｜证据充分性、生成、引用与拒答

服务端 pipeline：候选→授权/版本→证据是否直接回答问题（不能仅看相似度）→矛盾/时间核对→Context 序列化及源 ID→LLM→逐主张的 citation support / answer policy→允许回答、说明冲突或拒答。

**四类独立失败**：
1. Retrieval failure：正确证据未进候选。
2. Grounding failure：正确证据进入 Context，但回答脱离证据。
3. Citation failure：存在引用，但指向不支持结论的页码/版本。
4. Authority failure：内容支持结论但源已过期或越权。

NLI、相似度和 LLM Judge 的分数都不是事实正确性认证。拒答同时测错误作答和错误拒答，分别保留分母。对法规的有效期、来源优先级与证据冲突应有服务端策略，不让模型自行授权。检索文档属于不可信输入；其中的“忽略系统指令”不能升级成执行指令。

参考：[Ragas Faithfulness](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/faithfulness/)、[OWASP RAG Security](https://cheatsheetseries.owasp.org/cheatsheets/RAG_Security_Cheat_Sheet.html)、[原有 Ragas 评测](../RAGAS-EVALUATION.md)。

## R08｜真正能证明改进的评测

**不可混的四层**：
- Data QA：OCR/字段/表格/页码解析正确率，文档覆盖、过期/重复比例。
- Retrieval：Gold span/document Recall@K（相关证据条数/全部金标数），Hit@K（至少 1 个），MRR（第一个相关结果倒数名次），nDCG@K（考虑相关性等级的排序质量）；多个 gold 必须明确分母。
- Generation：Answer Correctness、Faithfulness、Citation Accuracy、误答率、误拒率、人工复核一致性。
- System：P50/P95、QPS、错误率、峰值并发、TTFT、Tokens、缓存命中及成本。

**正例与拒答分开**：Gold 为空的请求不应该除以零然后混入平均 Recall。预期拒答的分母要含越权/过期/知识缺失/矛盾四种场景。Metrics 与 OpenAI/Ragas 等实现可能有不同定义、输入字段和 Judge 模型，必须写全具体指标版本/代码。LLM-as-Judge 需要人工标注样本校准，不得把同一 LLM 自评当真实准确率。

**120 题起步 Gold Set 建议（计划，不是已存在数据）**：单文档25、编号20、语义改写20、跨文档15、OCR/表格15、多轮10、无证据10、权限5。附 query_type、gold_source_spans、reference、expected_abstain、principal/tenant、version、reviewer；按源文件分组防止同源复述泄漏到评测集。数据脱敏与许可优先。

**报告模板**：dataset_hash、split、parser/model/index/prompt revision、seed、K、Gold 标注口径、正负分母、Recall/MRR/nDCG、Faithfulness/引用/正确率、错误分类、CI/运行成本和失败样本链接。

参考：[BEIR](https://github.com/beir-cellar/beir)、[Ragas Metrics](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/)、[本仓合成任务评测](../labs/README.md)。

## R09｜索引更新、ACL、部署可靠性

**数据一致性**：source_id + revision 的幂等入库；原文、Chunk、向量、稀疏索引、引用映射带同一个 index_version；蓝绿切换读指针；删除传播和撤权传播需有时限与验证。旧文档不能仅仅“搜索时顺便忽略”，缓存结果、重排输入和引用读取也必须校验。

**权限**：服务端认证授权，不依赖 Prompt；tenant_id、document ACL、role、valid_on 需贯穿检索/上下文/引用/缓存。跨租户同文档编号、用户角色撤销后缓存、隐藏文档参与相似度混排是最小负例。

**性能**：将 P95 拆成 Query Rewrite、并发检索、RRF/Rerank、Context、LLM、验证、网络/排队；控制 N、batch size、CrossEncoder 算力、生成长度，按服务 SLO 调整。缓存键必须含身份/权限范围/索引版本，避免泄漏；日志 Trace 应脱敏，保留审计与回放所需的最小证据。

**交付条件**：权限与撤权测试、未授权泄漏=0、索引回滚、异常降级、数据删除、成本上限、可观测性、P95 压测报告；上线另走 [G0–G8](../../production/PRODUCTION-READINESS.md)。

## R10｜多模态 / GraphRAG / Agentic RAG

| 技术 | 与基础 RAG 的区别 | 使用判断 |
|---|---|---|
| OCR+Text RAG | 从图片提文字再走文本检索；无法等于图像理解 | 版式规整、视觉含义较少时首先试 |
| CLIP 图像检索 | 在兼容视觉-文本空间检索相似图 | 包装、图像目标，不等于法规问答 |
| VLM | 将图片/图表直接输入视觉语言模型 | 图表理解复杂但有模型成本与误读 |
| GraphRAG | 构造实体关系/社区摘要，以图结构补充上下文 | 大量跨文档关系、全局主题；索引贵 |
| Agentic RAG | 运行时决定是否、何时、向何处检索以及何时停 | 不固定的复杂问题；更多调用与风险 |
| Adaptive/Corrective | 根据检索难度或质量触发路由/补检 | 先证明基本召回是瓶颈再叠加 |

**不要混淆**：文本 BGE 向量与图片 CLIP 向量一般处于不同向量空间、维度未必相同；“两个索引分别召回再融合”与“直接混算余弦”不同。GraphRAG 官方源码称偏研究和维护模式，需特别评估索引成本。Agentic RAG 应测试工具预算/循环停止，不能因演示效果酷就默认采用。

参考：[Microsoft GraphRAG](https://github.com/microsoft/graphrag)、[Hugging Face Agentic RAG](https://huggingface.co/learn/agents-course/en/unit3/agentic-rag/agentic-rag)。

## 跨模块常见故障→定位顺序

| 症状 | 首查 |
|---|---|
| 查不到 | 源文档是否存在→解析/索引版本→ACL/时间→Query→召回 |
| 召回正确排序差 | RRF 候选范围→去重→CrossEncoder→上下文截断 |
| 答案有依据却错 | Context 顺序/冲突→Prompt/LLM→Answer Gate |
| 引用错 | 原文/Chunk/页码/索引版本映射，不要仅看模型措辞 |
| P95 上升 | Trace 队列→检索→Rerank→生成→Judge，逐阶段 Profile |
| 拒答多 | 无证据正例误拒 vs 真无答案，分桶看阈值 |
| 越权 | 立即阻断/审计，检查服务端过滤、索引及缓存，不靠微调 |
