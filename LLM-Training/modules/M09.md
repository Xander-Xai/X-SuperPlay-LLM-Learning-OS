## V3 深入：按当前需求直达本模块（不用先学完前面所有章）

**真实触发：** 为什么模型小到能加载，却在 GRPO Rollout+训练时显存爆掉？

### 机制：专业定义与输入/输出

训练消耗 weights/grads/optimizer/activations；推理有 KV Cache，RL 时还需要采样/策略/参考等状态。DDP 复制完整模型，ZeRO/FSDP 分片状态以空间换通信，verl 等框架可能让 rollout 与训练分时/分机运行。

### 大白话：它为什么有用

GPU 像一间有限的仓库：不仅要放商品（参数），还要存工具、打包材料、半成品；如果还让同一仓库兼任发货（rollout），即使商品很少也可能塞不下。

### 可执行学习任务（先证据后算法）

先以 PyTorch CUDA peak memory/profile 在同一 microbatch 上改变 seq_len、activation checkpointing；分开估算 Actor/Rollout/KV 缓存；单 GPU 只做架构图与小实验，未具备多卡不要伪造 scaling。

**失败注入 / 负例：** 反例：DDP 当成显存分片；`max_memory_allocated` 直接等同显卡总占用；在 GPU 不支持的版本中强行启用 FP8/vLLM colocate。
