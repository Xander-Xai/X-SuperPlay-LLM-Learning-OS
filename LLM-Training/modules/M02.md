### 机制：专业定义与输入/输出

Tokenizer 把原始字节映射为 Token ID；Packing/截断决定被监督的时间位置；去重和划分决定评测独立性。工具调用里的角色边界和 function 参数可能被截断。

### 大白话：它为什么有用

Tokenization 像将长文章分成有编号的零件；Packing 像往一个货箱装多份订单，装得满不代表订单边界正确。训练/测试同源近重复相当于考试前泄题。

### 可执行学习任务（先证据后算法）

取 20 条可公开/自造虚构产品语料，比较 tokenize 后长度、packing 与 truncation；按文档 ID 拆分，加入一条近重复污染样本，运行检测。比较 assistant-only 与 full-sequence 目标 token 数。

**失败注入 / 负例：** 反例：把工具 observation 算作答案；同一产品说明不同改写进入 train/test；一条对话被截断在 tool_call 内；不同 Tokenizer 的 PPL 被直接相减。
