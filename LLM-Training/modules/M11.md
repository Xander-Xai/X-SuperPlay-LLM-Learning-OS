## V3 深入：按当前需求直达本模块（不用先学完前面所有章）

**真实触发：** 既想低延迟又想高并发，同时不牺牲工具参数准确率怎么办？

### 机制：专业定义与输入/输出

Prefill 主要处理输入上下文并生成初始 KV，Decode 逐步输出 token；continuous batching、KV 管理、量化会改变吞吐、显存及尾延迟。TTFT 不是端到端延迟，冷启动与并发排队必须单独记录。

### 大白话：它为什么有用

推理服务像饭店：上菜时间不只由厨师下锅速度决定，也包括排队、备菜和端盘；增加桌数可能提升总接待量但拉长最慢顾客等待。

### 可执行学习任务（先证据后算法）

固定模型/tokenizer revision、Prompt/输出长度、并发，在 vLLM 可用环境对照 max_model_len、batching 或量化之一。记录 TTFT、E2E P95、吞吐、OOM、schema 及任务成功率；另做超时/回滚和故障演练。

**失败注入 / 负例：** 反例：只测一条热缓存请求；用质量不同的量化模型比纯延迟；LoRA merge 与 tokenizer 版本不符；生成 token 被错解析成 tool call。
