## V3 深入：按当前需求直达本模块（不用先学完前面所有章）

**真实触发：** 企业工具 JSON 经常填错参数，应该改 Prompt、Schema 还是训练 QLoRA？

### 机制：专业定义与输入/输出

SFT 对期望 assistant 输出进行监督；LoRA 在冻结底座上学习低秩增量，QLoRA 结合量化底座与可训练 Adapter。Assistant-only loss 仅监督指定 assistant token，工具 observation 是环境输入而非模型生成目标。

### 大白话：它为什么有用

SFT 像看优秀客服的示范动作；工具返回是仓库给客服的实时货单，不应要求客服‘凭空生成货单’。系统鉴权和工具副作用仍由后端负责，训练模型不能代替。

### 可执行学习任务（先证据后算法）

先跑 [合成工具网关](../labs/synthetic-tool-gateway/README.md) 验证白名单和证据，再用 Qwen 官方真实 tokenizer/template 打印 generation mask；再比较 0-training Prompt/Schema baseline 与 LoRA/QLoRA Tool SFT 的参数正确率和端到端任务成功率。

**失败注入 / 负例：** 反例：`assistant_only_loss=True` 但 chat template 无 generation 区间；新增无必要 special token；训练集中的 tool observation 被监督生成；模型输出 schema 合法却无访问权限。
